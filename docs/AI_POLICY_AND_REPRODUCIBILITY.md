# AI use and reproducibility policy for the jurimetrics portfolio

Applies to every jurimetrics article of the portfolio (Pricing Non-Pecuniary Harm;
The Geography of Judicial Delay; Do Binding Precedents Actually Bind?; Can Generative AI
Draft Legally Reliable Decisions?; Detecting Patterns of Abusive Litigation).
Master copy: `D:/Claude code - projetos/_shared-jurimetrics/`. Each repository keeps an
identical copy in `docs/` and may add a short "Journal-specific notes" section at the end.

Policies were verified on 2026-09-05. Re-check the target journal's page at submission time;
publishers revise these texts several times a year.

## 1. The constraint in one paragraph

Every publisher and funder consulted allows AI tools to *assist* research and permits
AI-assisted code, but (i) forbids listing an AI as author, (ii) requires a written
disclosure naming the tool, the version and the purpose, and (iii) forbids presenting
AI-generated content as the author's own writing. The Brazilian rule is now explicit:
Portaria CNPq 2.664/2026 (6 March 2026), art. 9, I, "c" and "d", requires declaring any
generative-AI tool used "em qualquer fase do desenvolvimento da pesquisa (concepção,
redação, análise de dados, submissão)", with tool and purpose, and states that "é vedada a
submissão de conteúdo gerado por IAG como se fosse de autoria humana", the authors being
"integralmente responsáveis pelo conteúdo final". The earlier DSGE paper's declaration
("documento organizado e redigido com auxílio de IA generativa") describes exactly the
pattern that current policies reject. The jurimetrics articles therefore separate roles:

| Layer | Who does it | AI allowed? | Disclosed? |
|---|---|---|---|
| Research question, design, identification strategy, interpretation, conclusions | Author | Brainstorm only; decisions are the author's | Not required (no text produced) |
| Code, tests, pipeline, repository infrastructure, docs of the repo | Author with Claude Code | Yes | Yes, in Methods and in the repository README |
| LLMs as *measurement instrument* (classification, extraction, drafting under test) | Pipeline designed and validated by the author | Yes, it is the method | Yes, fully described in Methods (model, version, hash, prompts, seeds, validation) |
| Article prose (Overleaf/LaTeX) | Author writes every sentence | Language polishing of author-written text only | Yes if beyond grammar/spelling; wording below |
| Tables and figures | Generated by scripts from data | Scripts may be AI-assisted (already disclosed as code) | No AI-generated images |
| References | Author verifies each one in the source | Never accept an AI-suggested citation without opening it | n/a |

## 2. Rules for Claude Code inside these repositories

1. Claude Code writes code, tests, SQL, configuration, runbooks and repository documentation.
   It does **not** write the article's prose: no paragraphs for `article/*.tex`,
   `article/*.qmd` or `paper/*.tex` beyond the mechanical skeleton (`\input` of tables and
   figures, section headings, placeholders marked `% AUTHOR WRITES`).
2. Every result that reaches the article comes from a script in the repository, run by the
   author, with its output saved under `outputs/`. No number is typed by hand.
3. Anything an LLM produces as part of the *method* (labels, extracted values, drafted
   decisions under evaluation) is stored with provenance: model name, exact version or
   hash, prompt file and version, temperature/seed, date, and the validation metrics
   against a human-annotated gold set. Only local models are used unless the author
   authorises a paid API in writing.
4. No personal data of parties, lawyers or individual judges appears in outputs, logs,
   commits or the article. Judges are analysed only at court or panel level.
5. No manuscript text is pasted into third-party AI tools that store inputs. Local models
   or tools with no-training terms only, and only for language polishing.
6. Every draft of the disclosure statement lives in `docs/latex_snippets/` and is copied
   into the Overleaf project by the author.

Practical consequence: one disclosure paragraph written for the strictest rule (CNPq +
Elsevier template + Wiley "did it influence conclusions") satisfies all of them. The
templates in section 5 are written that way.

## 4. Reproducibility standard for the GitHub repository

The repository must let a reader with R or Python and no contact with the author obtain the
same tables and figures. Checklist (each item is verified before a release):

- [ ] `README.md`: what the study is, status, one-command reproduction, and a step-by-step
      runbook (`docs/RUNBOOK.md`) numbered in execution order, saying what each step reads,
      writes, and how long it takes.
- [ ] Single language per repository as decided (R-only: articles 1 and 2; Python-only:
      articles 3, 4, 5). Where an earlier session wired both R and Python, the README states
      which one is the pipeline; the other is removed or clearly marked auxiliary.
- [ ] Environment pinned: `renv.lock` (R) or `requirements.lock`/`uv.lock` (Python) plus
      the interpreter version in the README; `sessionInfo()` or `pip freeze` saved to `logs/`.
- [ ] Data provenance: every download recorded in a manifest (URL, date, SHA-256, size,
      licence, filters). Raw data never modified and never committed; a script re-downloads
      it. Data licences (STJ CC-BY, DataJud terms, TJDFT) stated.
- [ ] Deterministic runs: seeds fixed and logged; LLM steps at temperature 0 with model
      hash; any sampling recorded with its seed.
- [ ] Numbered scripts or a `targets`/`Makefile` pipeline with a single entry point
      (`make all`, `targets::tar_make()`, `python scripts/run_all.py`).
- [ ] Tests (`tests/`) for parsers, extractors and key transformations, with tiny fixture
      files committed.
- [ ] `outputs/overleaf/` produced by a dedicated export script: `tables/*.tex` (booktabs,
      `\input`-ready), `figures/*.pdf` (vector) and `figures/*.png`, and `numbers.tex`
      with `\newcommand` macros for every number quoted in the text.
- [ ] `article/` (or `paper/`) contains only the Overleaf skeleton: `main.tex` with
      `\input{}` lines, the disclosure and availability snippets, `references.bib`.
      The prose is written by the author on Overleaf and synced back to the repo.
- [ ] `CITATION.cff`, `LICENSE` (MIT for code; CC-BY 4.0 for text and figures), `.gitignore`
      excluding data, logs, secrets and rendered files.
- [ ] Release tagged and archived on Zenodo before submission; DOI quoted in the
      data-availability statement.
- [ ] Personal-data check: no party, lawyer or judge names in any committed file or output.

## 5. Disclosure templates (copy from `docs/latex_snippets/`)

### 5.1 English, publisher-agnostic

Place before the references (Elsevier) or in Methods/Acknowledgements (others); also paste
into the submission form and the cover letter.

> **Declaration of generative AI and AI-assisted technologies.** During the preparation of
> this work the author used Claude Code (Anthropic; model Claude Fable 5.1; desktop app
> version [X.Y.Z]) to assist in writing, testing and documenting the data-collection,
> data-processing and estimation code released in the public repository, and to prepare
> the reproducibility documentation of that repository. The author designed the study,
> specified every procedure, reviewed and executed all code, and verified all outputs.
> [If applicable: An open-weights language model ([name, version, hash]) was used as a
> measurement instrument, as described in Section [Methods]; its outputs were validated
> against human annotation and did not replace the author's analysis.] No generative AI
> tool was used to write, draft or paraphrase the text of this article [if applicable:
> a language-editing tool ([name, version]) was used to check grammar and style of
> author-written text]. After using these tools the author reviewed and edited the
> content as needed and takes full responsibility for the content of the article.

### 5.2 Português (periódicos brasileiros, CNPq, SciELO)

> **Declaração sobre o uso de inteligência artificial generativa.** Na preparação deste
> trabalho o autor utilizou o Claude Code (Anthropic; modelo Claude Fable 5.1; aplicativo
> versão [X.Y.Z]) como apoio à escrita, ao teste e à documentação do código de coleta,
> tratamento e estimação disponibilizado no repositório público, e à documentação de
> reprodutibilidade desse repositório. A concepção do estudo, a especificação de cada
> procedimento, a revisão e a execução de todo o código e a verificação de todos os
> resultados foram realizadas pelo autor. [Se aplicável: um modelo de linguagem de pesos
> abertos ([nome, versão, hash]) foi empregado como instrumento de medida, conforme descrito
> na Seção [Métodos]; seus resultados foram validados contra anotação humana e não
> substituíram a análise do autor.] Nenhuma ferramenta de IA generativa foi usada para
> redigir, esboçar ou parafrasear o texto deste artigo [se aplicável: uma ferramenta de
> revisão linguística ([nome, versão]) foi usada para verificar gramática e estilo de texto
> escrito pelo autor]. Após o uso dessas ferramentas o autor revisou e editou o conteúdo
> conforme necessário e assume integral responsabilidade pelo conteúdo do artigo
> (Portaria CNPq 2.664/2026, art. 9º, I, "c" e "d").

### 5.3 Methods paragraph when an LLM is part of the method (articles 3, 4, 5)

> Automatic classification/extraction was performed with [model], an open-weights model run
> locally through [Ollama x.y / transformers x.y] with temperature 0 and fixed seed [s].
> Prompts are versioned in the repository (`prompts/vNN`). Performance was measured on a
> gold set of [n] documents annotated by the author [and a second annotator; Cohen's kappa =
> ...]: precision ..., recall ..., F1 .... Disagreements above [threshold] were audited
> manually. The model is a measurement instrument; no text it produced appears in this
> article, and its outputs are treated as probabilistic evidence, not as ground truth.

### 5.4 Data and code availability (English)

> **Data and code availability.** All code, the data manifest with URLs and SHA-256 hashes,
> the processed datasets that can be redistributed, and the scripts that generate every
> table and figure are available at https://github.com/[user]/[repo] (archived release:
> https://doi.org/10.5281/zenodo.[id]). Raw judicial texts are obtained from the official
> open-data portals cited in the manifest and are not redistributed; the repository
> re-downloads them. No personal data are released.

## 6. Pre-submission checklist

- [ ] Target journal chosen; its AI clause re-read on the day of submission; wording of 5.1
      or 5.2 adapted to the journal's placement rule (separate section, Methods or
      Acknowledgements) and pasted also into the submission form and cover letter.
- [ ] Tool versions filled in (Claude Code app version from the app's About dialog; model
      names and hashes from `logs/`).
- [ ] Every citation opened and checked by the author.
- [ ] Every number in the text traced to `outputs/overleaf/numbers.tex`.
- [ ] Zenodo DOI minted and pasted.
- [ ] If the author is a CNPq grantee or the work is CNPq-supported, the declaration is
      mandatory under Portaria 2.664/2026 regardless of the journal.
